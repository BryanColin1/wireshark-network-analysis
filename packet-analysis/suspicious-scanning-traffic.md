# Suspicious Scanning Traffic Analysis

## Objective

Analyze network traffic generated by an Nmap SYN scan and explain how scanning activity can appear in Wireshark.

## Environment

| Component | Description |
|---|---|
| Capture Machine | Kali Linux VM |
| Target Machine | Metasploitable 2 VM |
| Tool | Wireshark, Nmap |
| Network Mode | VirtualBox Host-Only Network |
| Source IP | Kali Linux VM |
| Target IP | `192.168.56.101` |

## Command Used

```bash
nmap -sS 192.168.56.101
```

## Packet Analysis

The following traffic pattern shows how an Nmap SYN scan can appear in Wireshark.

| Traffic Type | Source | Destination | Description |
|---|---|---|---|
| TCP SYN packets | Kali Linux VM | Metasploitable 2 VM | Scanner sends connection attempts to multiple destination ports |
| SYN-ACK responses | Metasploitable 2 VM | Kali Linux VM | Target responds when a scanned port is open |
| RST or no response | Metasploitable 2 VM / Network | Kali Linux VM | Closed or filtered ports may reset or ignore the connection attempt |

## Display Filter Used

```text
tcp.flags.syn == 1 && tcp.flags.ack == 0
```

## Key Observations

- The scan generated multiple TCP SYN packets from the Kali VM to the target.
- SYN packets were sent to multiple destination ports in a short period of time.
- This pattern is commonly associated with reconnaissance or port scanning.
- Additional responses such as SYN-ACK or RST packets can help determine whether ports are open or closed.
