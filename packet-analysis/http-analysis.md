# HTTP Request and Response Analysis

## Objective

Analyze HTTP traffic generated by requesting `http://example.com` and explain how a client sends a web request and receives a server response.

## Environment

| Component | Description |
|---|---|
| Capture Machine | Kali Linux VM |
| Tool | Wireshark |
| Network Mode | NAT |
| Source Host | Kali Linux VM |
| Destination | `example.com` |
| Destination Port | `80/tcp` |

## Command Used

```bash
curl http://example.com
```

## Display Filter Used

```text
http
```

## Packet Analysis

| Packet Type | Source | Destination | Description |
|---|---|---|---|
| HTTP Request | Kali Linux VM | `example.com` | Client sends a `GET / HTTP/1.1` request |
| HTTP Response | `example.com` | Kali Linux VM | Server responds with `HTTP/1.1 200 OK` |

## Key Observations

- The client sent an HTTP GET request to retrieve the main page from `example.com`.
- The server responded successfully with `HTTP/1.1 200 OK`.
- HTTP traffic is readable in Wireshark because it is not encrypted.
- The request and response occurred after the TCP three-way handshake was completed.

## Security Relevance

HTTP analysis is important because unencrypted web traffic can expose request details, headers, URLs, and sometimes sensitive data. In real environments, HTTPS should be used to protect confidentiality and integrity.
